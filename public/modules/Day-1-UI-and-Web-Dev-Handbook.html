UI component and asset libraries

Do not build every button from scratch. Pick ready-made components, install them into your project, then ask the AI to wire them together.

React Bits

Animated React components in four groups: text animations, animations, components and backgrounds. Four code variants (JS or TS, CSS or Tailwind).

21st.dev

Community registry of React + Tailwind components built on shadcn/ui. Browse, copy a prompt or an install command.

shadcn/ui

Accessible base components (button, card, dialog, form) copied into your project so you own the code.

Aceternity UI

Eye-catching animated sections: hero effects, cards, backgrounds.

Animated components and landing-page blocks for React + Tailwind.

daisyUI

Unsplash / Pexels / unDraw

Awwwards / Dribbble / Land-book

Inspiration: study layouts before you prompt.

Pick your path

Path A: No install

Use an AI app builder in the browser (v0, Lovable, Bolt.new, Google AI Studio). Best if your laptop is slow or you are new to code. Skip to “Prompting”.

Path B: Local project

Vite + React + Tailwind + shadcn/ui in an AI editor such as Cursor or VS Code. Best if you want to learn how real sites are built. Follow “Zero to finish”.

Zero to finish: build a site locally (Path B)

1

Install the basics

  • Node.js (LTS version) from nodejs.org
  • An editor with AI: Cursor, or VS Code with GitHub Copilot
  • A GitHub account (for hosting later)
node -v
npm -v

Both commands should print a version number.

2

Create the project

npm create vite@latest portfolio -- --template react-ts
cd portfolio
npm install
npm run dev

Open the local address it prints (usually http://localhost:5173). You should see the Vite starter page. Leave this running.

3

Add Tailwind CSS

In a second terminal, in the project folder:

npm install tailwindcss @tailwindcss/vite

Add the plugin to vite.config.ts and put @import "tailwindcss"; at the top of src/index.css. If anything differs, follow the current guide at tailwindcss.com/docs (Vite).

4

Add shadcn/ui

npx shadcn@latest init
npx shadcn@latest add button card badge

The init command checks your setup and tells you what is missing. If it asks for a path alias, the shadcn Vite guide (ui.shadcn.com/docs/installation/vite) shows the tsconfig change.

5

Add animated pieces from React Bits

npx shadcn@latest add @react-bits/BlurText-TS-TW

The name pattern is @react-bits/ComponentName-Variant. TS-TW means TypeScript + Tailwind, which matches this project. Each demo page on reactbits.dev shows its own install command and props.

6

Add sections from 21st.dev

Find a component (hero, pricing, navbar, footer), then either copy its prompt into your AI editor or run the install command shown on its page. The pattern looks like:

npx shadcn@latest add "https://21st.dev/r/<author>/<component>"

Replace the placeholders with the real values from the component page.

7

Let the AI assemble it

Open the project in Cursor or VS Code and prompt in small steps (see next section): layout first, then each section, then polish. Run npm run dev after every change and look at the browser.

8

Build and publish

npm run build

This creates a dist folder. Upload the project to GitHub, then connect it to Netlify, Vercel or Cloudflare Pages (all can deploy a Vite project from a repository). For GitHub Pages, set the base option in vite.config.ts to your repository name.

Commit often. After each working step run git add . && git commit -m "hero done". If the AI breaks something, you can go back.

How to structure a prompt

A good UI prompt answers the same questions a designer would ask. Use these parts:

PartSayExample
GoalWhat you are building and for whomA personal portfolio for a first-year CS student, read by recruiters
StackTools to useReact, TypeScript, Tailwind, shadcn/ui
StructureSections in orderNavbar, hero, about, skills, 3 project cards, contact, footer
StyleColours, fonts, moodDark navy background, violet accent, Inter for text, serif for headings
ComponentsWhat to reuseCard and Badge from shadcn/ui; BlurText from React Bits for the hero
BehaviourInteractionsSmooth scroll, hover lift on cards, mobile menu
ConstraintsRulesMobile first, readable contrast, no new libraries without asking
OutputHow to answerList the files you will change first, then make the change

First prompt (copy and edit)

You are a senior front-end developer.
Build a personal portfolio website for [your name], a [your role].
Stack: React + TypeScript + Tailwind + shadcn/ui.
Sections in order: navbar, hero (name, one-line pitch, two buttons), about, skills (badges), projects (3 cards with image, title, one-line outcome, link), contact, footer.
Style: [dark/light], accent colour [colour], headings in [font], body in Inter. Generous spacing, rounded cards.
Behaviour: smooth scroll navigation, card hover effect, responsive mobile menu.
Constraints: mobile first, good contrast, keep components small and reusable, use placeholder text I can replace.
First tell me the plan and file list in 5 lines. Then build the navbar and hero only.

Refinement prompts

Make the hero feel more premium: bigger heading, more space, subtle gradient background. Change only Hero.tsx.
The cards look flat. Add a soft border, hover lift and consistent padding. Do not change the content.
It breaks on a 375px wide screen. Fix the layout for mobile and tell me what you changed.
Replace the placeholder text in About with this: [paste your text]. Keep the layout.
The page console shows this error: [paste error]. Explain the cause in one line, then fix it.
Loop: plan → build one section → look at it → refine → commit. One change per prompt gives better results than one huge prompt.

Instructions for your AI agent

AI editors read a rules file so you do not repeat yourself in every prompt. Name it for your tool: AGENTS.md (works across many tools), .cursor/rules (Cursor) or CLAUDE.md (Claude Code). Put it in the project root.

# Project rules
- Stack: React + TypeScript + Tailwind + shadcn/ui. Do not add other UI libraries without asking.
- Components live in src/components. One component per file, PascalCase names.
- Use Tailwind classes; no inline styles. Colours come from the theme variables in index.css.
- Mobile first. Check layouts at 375px, 768px and 1280px.
- Text must have readable contrast in light and dark mode.
- Never delete content I wrote. If you change a file, say which one and why.
- Before big changes, show a short plan and wait for my OK.
- Never put API keys in code. Use environment variables.

Good agent instructions are specific (name the stack and folders), checkable (“375px”, not “works on phones”) and bounded (what it must not touch).

UI recreation challenge playbook

You get a reference design and a timer. Work in this order:

  1. Read it (3 min). Note the sections, the grid (how many columns), the fonts, the 3–4 main colours and the spacing between sections.
  2. Give the AI the picture. Attach a screenshot to an AI that accepts images and use the prompt below.
  3. Skeleton first. Layout and sections with plain text, then typography, then colours, then details such as shadows and hover effects.
  4. Compare side by side. Zoom the browser to match the reference, check spacing and alignment.
  5. Test small screens. Resize the window; fix what overflows.
Recreate the attached design as a responsive web page using [stack].
Match: layout and column grid, font sizes and weights, colours (sample them from the image), spacing between sections, button and card styles.
Do not copy logos, text or images that belong to someone else; use placeholders.
Build in this order: 1) page skeleton, 2) typography and colours, 3) components, 4) hover and focus states.
After each step, list what still differs from the image.
Judges look at the web development outcome: fidelity to the reference, responsiveness and clean interactions.

Build your digital portfolio

Prepare this content before you prompt, so the AI builds around real material:

  • Name, role and a two-line bio
  • A one-line pitch for the hero
  • 3 projects: title, one sentence on what it does, link, screenshot
  • Skills list (8–12 items)
  • Contact links: email, GitHub, LinkedIn
  • One accent colour and two fonts

Sections to include

SectionPurposeTip
HeroSay who you are in 5 secondsBig name, one-line pitch, a clear button
AboutShort human storyKeep it under 80 words
SkillsShow your toolboxGroup them: languages, frameworks, tools
ProjectsProof of workResult first, then the tech used
ContactMake it easy to reach youA visible email or button

UI design rules that fix most pages

RuleDo this
HierarchyOne main heading per page; sizes step down clearly (for example 48 / 32 / 20 / 16 px)
SpacingUse a scale (8, 16, 24, 32, 48, 64 px) and repeat it everywhere
ColourAbout 60% background, 30% surface colours, 10% accent. One accent colour only
ContrastText must be readable on its background in both light and dark mode; test with your browser’s accessibility checker
TypographyTwo fonts at most; line length about 60–75 characters; line height 1.5–1.7 for body text
AlignmentPick a grid and keep edges aligned; centre only short text
StatesEvery button and link needs hover and keyboard-focus styles
ResponsiveDesign for 375px first, then 768px, then 1280px
ImagesCompress; give every image an alt description

Troubleshooting

ProblemTry this
npm command not foundInstall Node.js LTS, then restart the terminal
Page is blank after an AI changeOpen the browser console (F12); paste the first red error into the AI
Styles not applyingCheck that Tailwind is imported in index.css and that the dev server was restarted
AI changed things you did not ask forUndo with git, then repeat the prompt with “change only [file]”
Component install failsRun the exact command from the component page; make sure shadcn init finished first
Layout breaks on phonePrompt: “fix overflow at 375px; list every element you changed”
Text hard to read in one themeUse theme colour variables instead of fixed colours; ask the AI to audit contrast

Finish line

  • Site runs with no errors in the browser console
  • Works at phone, tablet and desktop widths
  • All text readable; links and buttons have hover and focus styles
  • Real content replaced every placeholder
  • Pushed to GitHub and, if possible, published with a link
  • You can explain which prompt produced which part (this is what you demo)
Stay safe. Read the code the AI writes before you ship it. Never paste passwords or API keys into a prompt. Check licences on images and fonts. Keep personal details on your portfolio to what you are happy to make public.
