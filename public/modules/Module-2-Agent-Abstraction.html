Movement 2: Understand + Connect

Agent abstraction

How we got from standalone models to agents, and the characteristics that define them.

Think about the last time you asked Gemini or any other AI to do something for you. Maybe you asked it to help plan a trip, manage your calendar, or analyze some data. It probably gave you great advice, like detailed steps, helpful suggestions, or even some sample code. But then what? You still had to do all the actual work yourself.

This gap between knowing and doing represents the next significant step in the evolution of AI. While we have incredibly intelligent systems capable of advising us on a vast array of tasks, the final execution still rests on our shoulders. It’s akin to having a world-class advisor who can’t pick up the phone, send an email, or press a button on your behalf.

The solution: The agent abstraction

Why agents are different

An agent isn't just an LLM with tools bolted on. It's a fundamentally different abstraction, a system that can pursue goals autonomously. Instead of responding to each request in isolation, an agent maintains context, plans ahead, and takes initiative to achieve objectives.

Not everything that uses an LLM and tools is an agent. Breaking down this definition, true agents are characterized by autonomous operation, reasoning and planning, continuous learning, and environmental awareness.

Observing these characteristics at work

Let’s explore how these characteristics manifest with a simple example: checking the weather and deciding what to wear.

With an LLM

You: "Should I wear a jacket today?"

LLM: "I don't have access to current weather data, but generally you should wear a jacket if it's below 60°F or raining."

The LLM has knowledge but no connection to reality. ❌ No environmental awareness, ❌ no tool use.

With LLMs and function calling

You: "Check the weather for Seattle"

LLM: [Calls weather API]

Result: "It's 55°F and cloudy in Seattle"

You: "Should I wear a jacket?"

LLM: "Yes, at 55°F you should wear a jacket"

Better—it can use tools, but you're managing the conversation flow. ✅ It uses tools, ❌ but it isn’t autonomous or proactive.

With an agent

You: "Should I wear a jacket today?"

Agent: 
[Checks your location]

[Queries weather API]

[Checks your calendar for outdoor activities]

[Considers the forecast for when you'll be outside]

Agent: "Yes, definitely wear a jacket. It's 55°F now, but it will drop to 48°F by 6 PM when you have your outdoor meeting."

The agent autonomously gathered context and provided a complete answer. ✅ All five characteristics are in action.

Problems only agents solve

Complex multi-step workflows

Consider expense report processing. An agent can extract receipts from emails, categorize expenses, check against policy, route for approval, and update accounting systems—all from a single request. This requires goal-directed behavior, autonomous operation, and tool use working in concert.

Dynamic problem solving

When booking travel, an agent can handle the reality that flights sell out, prices change, and schedules conflict. It adapts its approach based on what it discovers through environmental awareness and proactive initiative.

Ongoing task management

Agents can monitor situations and take action when needed. “Keep track of flight prices to Tokyo, and book when they drop below $800” isn’t a one-time query. It’s an ongoing responsibility that requires all five characteristics to function effectively.

Integrated experiences

Instead of using five different tools to accomplish one goal, agents can coordinate across multiple systems seamlessly. Planning an event might involve calendar systems, venue databases, catering services, and invitation platforms—an agent can orchestrate all of these autonomously using the appropriate tools.

Key takeaways

The agent abstraction represents a fundamental shift in how we think about AI systems:

  • From reactive to proactive: Agents don’t just respond; they pursue goals.

  • From isolated to integrated: Agents maintain context and state across interactions.

  • From advisory to executive: Agents don’t just tell you what to do; they do it.

  • From static to adaptive: Agents adjust their approach based on what they learn.

This isn’t just an incremental improvement, but a paradigm shift enabling entirely new application categories.
